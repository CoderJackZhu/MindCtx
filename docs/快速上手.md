# MindDoc 快速上手

## 5 分钟入门

### 第一步：创建文件

打开命令面板（Ctrl/Cmd+P），输入 `MindDoc: 创建 MindDoc 文件`，插件会自动生成一个带有基础结构的 `.mind.md` 文件并打开 MindDoc 视图。

或者手动创建任意 `.mind.md` 文件，内容如下：

```markdown
---
minddoc: true
---

# 我的第一个大纲

## 主题一

## 主题二
```

### 第二步：编辑节点

- **双击**节点标题进入编辑模式
- **Enter** 确认编辑
- **Escape** 取消编辑

### 第三步：组织结构

- 按 **Enter** 在选中节点下方创建新的兄弟节点
- 按 **Tab** 将节点缩进为上一个兄弟的子节点
- 按 **Shift+Tab** 将节点提升一级
- **拖拽**节点到目标位置（上方/下方/内部）

### 第四步：切换视图

点击工具栏右侧的「脑图」按钮，或使用命令面板「MindDoc: 切换视图」。

## 核心概念

### Markdown 就是数据

MindDoc 不使用专有格式。你的大纲数据始终是标准 Markdown：

- `# 标题` → 树的分支节点
- `- 列表项` → 树的叶节点
- 标题下的段落 → 节点的「备注」
- 代码块/引用块 → 节点的「附属内容」

这意味着：
- 其他 Markdown 编辑器可以正常打开你的文件
- Git diff 可以清晰显示结构变更
- 你不会被锁定在任何工具中

### heading-depth 参数

`heading-depth` 控制「标题」和「列表项」的分界线：

```markdown
---
heading-depth: 3
---
```

- 深度 1-3 的节点输出为 `#`、`##`、`###` 标题
- 深度 4+ 的节点输出为缩进的列表项

示例：当 `heading-depth: 2` 时：

```
根节点          → # 根节点
├── 子节点 A    → ## 子节点 A
│   ├── 孙节点  → - 孙节点       （深度 3 > heading-depth 2，变成列表）
│   │   └── 曾孙  → - 曾孙       （缩进列表）
```

### 往返保真

MindDoc 的核心设计原则：**不修改的内容保持原样**。

即使你的 Markdown 有不规范的空行、缩进或格式，只要你没有通过 MindDoc 编辑那个节点，序列化回文件时这些内容会原样保留。只有被编辑的节点才会被重新生成。

## 日常工作流

### 会议记录

1. 会前用 MindDoc 列出议程（脑图视图做全局规划）
2. 会中切换到大纲视图逐条记录
3. 会后拖拽调整结构，整理行动项（添加 `- [ ]` 任务）

### 知识整理

1. 阅读时随手记录关键点
2. 用 Tab/Shift+Tab 调整层级关系
3. 用脑图视图检查整体结构是否合理
4. 导出为 AI 上下文，让 AI 帮助补充细节

### 项目规划

1. 用脑图视图做头脑风暴（自由添加节点）
2. 切换到大纲视图精细化排列
3. 添加任务复选框标记里程碑
4. 嵌入到项目主页 Markdown 中展示进度
